# Gmail Price Alerts untuk Alya

Workflow terpisah [Anshel · Gmail Flight Alerts · Alya](../workflows/office_gmail_flight_alerts.json) berjalan di n8n Cloud setiap 15 menit setelah dipublikasikan. Workflow Lead Hunter dan jadwal existing tetap dipakai. Intake menggunakan kredensial HTTP Header Auth Anshel yang sama dengan scheduler dan memanggil outbox Alya yang sudah ada. State alert disimpan di agregat transaksi privat Supabase. Tidak ada migration atau Telegram Trigger baru.

## Hubungkan akun Gmail di n8n Cloud

1. Di [Gmail](https://mail.google.com/), buat label `Anshel/FlightAlerts`. Buat filter terpisah untuk Google Flights dan Traveloka. Batasi **From** ke pengirim resmi dan **Subject** ke Price Tracking atau Price Alert. Terapkan label tersebut saja. Setelah email pertama muncul, buka **Show original**, cocokkan alamat dan subjek filter serta periksa hasil DKIM dan DMARC. Jangan gunakan filter domain saja tanpa subjek.
2. Buka [n8n existing](https://n8n-s75gjxx8g8lx.jkt6.sumopod.my.id/) dan impor `workflows/office_gmail_flight_alerts.json` dari GitHub. Simpan workflow dalam keadaan belum dipublikasikan. Di **Credentials**, buat **OAuth2 API** (generic), pilih **Authorization Code**, dan salin **OAuth Redirect URL** yang ditampilkan n8n.
3. Di [Google Cloud Console](https://console.cloud.google.com/apis/library/gmail.googleapis.com), aktifkan Gmail API di proyek yang Anda kendalikan. Di **Google Auth Platform**, isi **Branding**, atur **Audience**, dan tambahkan akun Gmail pemilik sebagai test user jika status aplikasi masih Testing. Di **Clients**, buat OAuth client jenis **Web application**. Masukkan URL callback n8n tadi pada **Authorized redirect URIs**.
4. Masukkan client ID dan secret hanya ke credential n8n. Gunakan **Authorization URL** `https://accounts.google.com/o/oauth2/v2/auth`, **Access Token URL** `https://oauth2.googleapis.com/token`, scope `https://www.googleapis.com/auth/gmail.readonly`, opsi auth query `access_type=offline&prompt=consent`, dan **Authentication: Body**. Klik **Connect my account** dan selesaikan dialog persetujuan Google sendiri. Scope ini dapat membaca seluruh mailbox. Filter workflow membatasi pesan yang dibaca oleh workflow, sedangkan scope OAuth memberi akses baca mailbox. Mode Google Testing dapat membuat refresh token kedaluwarsa setelah tujuh hari. Untuk penggunaan berkelanjutan, ikuti persyaratan Google Auth Platform yang berlaku pada akun dan scope ini.
5. Pilih credential OAuth tadi pada node Gmail. Pilih credential **HTTP Header Auth** worker Anshel pada node **Catat autentikasi Gmail** dan **Intake Flight Tracker Alya**. Pertahankan pengaturan penyimpanan execution content dalam keadaan nonaktif. Publikasikan workflow. Setelah satu interval, cek **Gmail Connected** dan **Waiting for First Alert** pada dashboard atau gunakan `/diagnosa` melalui Bima. Jika Google menolak OAuth, berhenti pada langkah tersebut. Alternatif forwarding memerlukan tujuan mailbox khusus yang telah diverifikasi dan autentikasi asli yang dapat dipertahankan. Alur forwarding belum dipasang.

[Dokumentasi OAuth Google](https://developers.google.com/identity/protocols/oauth2/web-server) · [Scope Gmail](https://developers.google.com/workspace/gmail/api/auth/scopes) · [Filter Gmail API](https://developers.google.com/workspace/gmail/api/guides/filtering)

## Saat alert pertama masuk

- Untuk Google Flights, gunakan watch aktif SUB → BTH, rolling, sekali jalan, satu penumpang ekonomi, provider **Semua provider terhubung** atau **Google Flights**. Rentang rolling adalah pengaturan Anshel. Alert Any Dates dapat mewakili minimum di rentang yang dipilih Google. Riwayat minimum rute terpisah dari penawaran penerbangan tertentu.
- Untuk Traveloka, siapkan watch aktif tanggal spesifik dengan rute dan tanggal yang sama. Parser membutuhkan tanggal yang eksplisit. Alya menampilkan harga sebelumnya dan selisih hanya jika email memuat harga yang sebanding dalam mata uang yang sama. Stop di Anshel tidak mengubah pengaturan alert akun provider.
- Polling membaca pesan baru berlabel, memeriksa autentikasi penerima Gmail dan menyimpan data yang dinormalisasi saja. Pesan yang cocok masuk histori, dan Alya mengirim melalui outbox dengan pemeriksaan revision watch. Pesan ulang dikenali dengan Gmail Message ID dan fingerprint konten. Tidak ada browser, laptop, scraping, atau request ke Traveloka.
- Verifikasi format pertama melalui pesan asli yang sudah disamarkan jika dashboard melaporkan `unsupported_format`. Tes sintetis memakai format eksplisit bahasa Indonesia atau Inggris. Cakupan format provider belum diverifikasi dengan email aktual. Jangan kirim fixture ke endpoint atau Telegram produksi. Google dan Traveloka menentukan perubahan mana yang menghasilkan email.
